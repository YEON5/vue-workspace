# 코드 정리·검증 후 동기화

순서: 범위 확인 → 정리 → 검증 → git-sync 절차로 push

## 1. 범위 확인
- `git status`와 `git diff HEAD`로 이번에 바뀐 파일과 코드만 확인한다. 새로 추가된(untracked) 파일도 포함한다.
- 바뀌지 않은 코드는 정리 대상이 아니다.

## 2. 정리 (simplify)
바뀐 코드에서 다음을 찾는다.
- 중복 코드
- 쓰이지 않는 변수, 함수, import
- 디버그용 출력(console.log, print 등)과 주석 처리된 코드
- 불필요하게 복잡한 로직

고칠 부분을 파일별 목록으로 보여 주고, 사용자가 승인한 것만 수정한다.
동작이 바뀔 수 있는 수정은 따로 표시하고 반드시 확인받는다.

## 3. 검증
- 프로젝트에 정의된 검증 명령을 찾는다. (예: package.json의 lint/test/build 스크립트, Makefile, pytest 설정)
- 찾은 명령을 실행하고 결과를 요약해서 알린다.
- 검증 명령이 없으면 그 사실을 알리고 어떻게 검증할지 사용자에게 묻는다.
- 실패하면 원인을 보여 주고 멈춘다. 실패한 상태로 push하지 않는다.

## 4. 동기화
검증을 통과하면 git-sync 스킬의 작업 사이클(파일 확인 → add → commit → pull → push)대로 진행한다.
